# PDS Phase 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Questions 34–40 and References & ID tabs, PDF page 4 filled, teacher area with My Profile, principal/admin download of a teacher's PDS.

**Architecture:** New nullable columns on `PersonalDataSheet` + `PdsReference` entity; two form types with their own validation groups; `TeacherController` + teacher layout; `ProfileController` opened to teachers via a security expression; `SchoolTeacherController::pds()` reuses `PdsPdfRenderer`.

**Spec:** `docs/superpowers/specs/2026-10-16-pds-phase3-design.md`

## Global Constraints

- No git; TDD per task; full suite at the end (never two phpunit runs at once).
- Groups: `PersonalDataSheet::QUESTIONS = 'questions'`, `PersonalDataSheet::REFERENCES = 'references'`; constraints on new fields only in their own group (never Default) so other tabs never block.
- Migration via make:migration, migrate dev + test.
- Question wording copied from the xlsx (page 4).

## Review Focus

1. A principal can't download a PDS of a teacher from another school or of a former teacher (not in current SY) — Task 4 tests.
2. The download doesn't create/flush a PDS row for the teacher — Task 4 test.
3. Choosing "No" after "Yes" clears details so the PDF doesn't print stale details — Task 1 test.
4. All three references empty is valid; any one filled requires all three — Task 2 test.
5. Teacher layout used on every profile page for teachers (no principal nav leaks) — Task 3 test.
