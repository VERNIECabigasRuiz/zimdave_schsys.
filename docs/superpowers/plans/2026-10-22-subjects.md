# Subject Offerings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Schools set the subjects they offer per school year (per grade level, SHS narrowed by semester/track/strand, MAPEH-style components), filled from a DepEd preset or brought back from last year; managed by admin/principal, and by Individual-plan teachers for their own section's grade.

**Architecture:** A `Subject` entity per school + school year + grade level, mirroring `Section`. All writes go through `SubjectManager` (plan-blocked = view-only, activity log). One shared controller/template set serves admin and principal (`/schools/{id}/subjects`); a teacher controller reuses the templates for the Individual plan. The DepEd preset is a fixed list in `src/Data/DepEdSubjects.php`, like `PhilippineDivisions`.

**Tech Stack:** Symfony 8.1, PHP 8.4, Doctrine ORM 3 (MariaDB 10.4), Twig, Stimulus (AssetMapper), PHPUnit 13.

**Spec:** `docs/superpowers/specs/2026-10-22-subjects-design.md`

## Global Constraints

- Project root `C:\xampp\htdocs\zimdave_schsys`; PHP is `C:\xampp\php\php.exe`; run tests with `php bin/phpunit` (one phpunit process at a time — tests share the `zimdave_schsys_test` DB).
- No git commits unless the user has set up git and asked; "Commit" steps below are skipped otherwise.
- TDD: every step that adds behavior starts with a failing test, run and seen failing.
- Schema changes only via `php bin/console make:migration` then `doctrine:migrations:migrate --no-interaction` for dev **and** `--env=test` (never `schema:update`).
- Every write goes through `SubjectManager`, which throws `PlanLimitException` when `PlanLimits::blockedReason($school)` is not null.
- Pages work on the current school year only (`SchoolYearRepository::findCurrent()`), like Sections.
- Code: trimmed, stored uppercase, `^[A-Z0-9-]+$`, max 20, unique per school + S.Y. Name: max 100, unique per school + S.Y. + grade + semester.
- Exact user-facing copy: "The code MATH7 is already used this school year." · "Grade 7 already has a subject named Mathematics." · "Create your section first." · "This also deletes its N components." · log lines `Created subject <label>`, `Updated subject <label>`, `Deleted subject <label>` (+ ` with N components`), `Added N DepEd subjects for Grade 7`, `Brought back N subjects`.
- Labels: `MATH7 – Mathematics`; component `MA7 – Music and Arts (MAPEH)`.
- Follow the Sections code as the pattern: `SectionManager`, `SectionRepository::findBringBackCandidates`, `SchoolSectionController`, `templates/school_sections/*`, `section_form_controller.js`, `SchoolSectionControllerTest`.

## Review Focus

1. Bring back / DepEd set into a year that already has a subject with the **same name but a different code** in that grade must skip it, not create a duplicate name (the name rule is a validator, not a DB index) — Task 3 test `testBringBackAndDepEdSkipDuplicateNames`.
2. A principal posting a `parent` id from **another school or another grade** (tampered form) is rejected with a form error, not saved — Task 4 test `testTamperedParentRejected`.
3. Bring back of a subject whose grade the school **no longer offers** (school type changed) is skipped — Task 3 test `testBringBackSkipsGradesTheSchoolNoLongerOffers`.
4. An Individual-plan teacher opening `/teacher/subjects/{id}/edit` for a subject of **another grade** gets 404, and posting another grade is rejected — Task 5 test `testTeacherCannotTouchOtherGrades`.
5. Editing a parent's semester/track/strand updates its components, and a component submitted with different SHS values still ends up with the parent's — Task 3 test `testComponentsFollowParentShsSettings`.
